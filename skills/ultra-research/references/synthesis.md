# Baseline synthesis and validation

Read this reference after the selected research lanes are complete.

## Traceability check

Verify that each accepted outcome has:

1. supporting problem, user, or constraint evidence;
2. an explicit decision and scope boundary;
3. testable acceptance behavior;
4. a compatible architecture or delivery path;
5. a named unresolved blocker when any link is missing.

Check the reverse direction as well: every proposed component, dependency, and quality
requirement must support an accepted outcome or constraint.

## Consistency check

- Use one term for each actor, boundary, and authoritative data source.
- Remove duplicate narratives and stale alternatives.
- Keep source links next to the claims they support.
- Separate durable decisions from volatile external facts.
- Preserve explicit non-goals and rejected alternatives only when they prevent a
  likely future mistake.

## Handoff

Report:

- validated scope and decisive evidence;
- specification files changed;
- accepted decisions and material uncertainty;
- blockers, or an explicit statement that none remain;
- one next action.

Do not create a parallel summary document solely for model consumption. The planning
workflow should read the smallest authoritative baseline sections it needs.
