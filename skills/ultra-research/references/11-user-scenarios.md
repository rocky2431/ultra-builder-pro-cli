# User scenarios

Use for workflow step `11-user-scenarios`.

## Objective

Trace the important current and intended journeys from trigger through outcome,
including failure and recovery.

## Method

- Bind each scenario to an evidence-backed actor and entry point.
- Describe the current path before proposing a changed path in brownfield adoption.
- Include state changes, external systems, permissions, and observable outcomes.
- Do not force a fixed scenario count or emotional narrative.

## Record

Update `product.md` with scenario id, actor, trigger, preconditions, current or intended
flow, success outcome, failure outcome, recovery, and evidence. Mark gaps where runtime
behavior and documentation disagree.

Complete the step with evidence references and the updated output path.

## Semantic record

Use kind `scenario`. Record `actor_id`, `trigger`, `preconditions`, `flow`, `success`,
`failure`, and `recovery`.
