# Adversarial review evaluation

Use this protocol before changing the permanent lens roster. A plausible blind spot is
a hypothesis; admit a new lens only when a blind evaluation shows unique useful coverage.

## Prepare a blind fixture

Create or select a small repository snapshot containing known defects across acceptance,
premise, executable behavior, tests, recovery, design, and maintained documentation.
Keep the seed manifest outside every Worker Packet. Record the snapshot revision,
accepted intent, North Star Trace, public seams, and commands available to workers.

## Compare equal runs

Run the current six-lens roster first. Then run the candidate lens with the same packet,
tool authority, model family, and bounded effort. Use isolated contexts where the host
supports them and record the actual execution mode. Do not reveal seed ids, expected
findings, earlier outputs, or the admission decision to either run.

After artifacts are stable, map evidence-backed findings to the hidden seeds. Preserve
misses, false positives, unavailable evidence, and disagreements; a vote or score does
not decide truth. Repeat any claimed unique catch against a fresh context so leaked
context or sampling noise is not mistaken for a durable capability.

## Admission decision

Add a permanent lens only when it repeatedly finds a consequential, reproducible defect
class the current roster misses and its question cannot be folded into an existing lens
without losing independence. Otherwise strengthen the narrowest existing lens or keep
the candidate as an occasional blind cross-family probe. Record the fixture revision,
raw artifact paths, mapping rationale, decision, and cheapest future retest.
