**适用产物：** 本次第四步运行中 **F2 开发案例（模糊会议记录产品）交付的产物**。

**为何选它（而不是 F1/F3）：** F1 与 F3 的判据是**冻结测试**，独立验收者跑一遍 `npm test`
就已被既有材料覆盖；F2 是唯一**用途来自脚本化 Owner 答案、没有冻结测试**的案例——

第一步正是在 F2 上记到「有可用功能但漏问实质用途」，所以 F2 的交付行为是第四步必须核对的那一项。

**输入：** 无新增 Owner 消息。核对基准是 F2 案例**已冻结的用途答案**
（单人自用、按关键词找回、能看到日期），由 `owner_answer_script` 定义，本补篇不改一字。

**独立验收者的资格：** 未参与该产物的实现，也未参与第二、三步的实现。

**必须亲手做的事（无模型环、逐条记录命令与真实输出）：**

1. 在**干净副本**上按产物自带说明启动它——不看实现源码猜用法。说明缺失或与实际不符本身是观察。
2. 记一条会议记录，**换一个新进程**再按关键词把它找回来，确认结果里能看到日期。
3. 关掉进程后重新打开，确认记录仍在（跨进程持久）。
4. 检查这三步的执行路径上没有 mock/stub 顶替真实读写。
5. 记录任何**做不到**的事：说明不足、命令报错、需要读源码才能用、需要手工造数据。

**判据：** 冻结用途的三件事（记录、按关键词找回、看到日期）在独立操作下真实成立，
且交付声明与实际行为一致。**明确禁止**用"测试全绿""文件齐全""工具调用很多"替代上述任一条；

## 七、D4：用户要求的真实中断与显式续接

### 7.1 目标选择与理由（用实测窗口，不猜）

第一步逐轮实测墙钟（`step1-baseline-observations.json`，同一 native 2.1.263 / `claude-opus-5[1m]`）：
F1t1 97.43s、F1t2 153.34s、F2t1 **326.70s**、F3t1 77.25s、F3-s2 95.78s。

**尝试 1 的目标：** D2 的那条冻结请求（"想看某一段时间里记的东西"），跑在**另一份独立副本**上。
这样 D2 本身就是**同条件、未被中断的对照**：D2 的实测墙钟给出这条请求的真实工作窗口，
D4 的中断点与等待上限由它决定，而不是由我预设一个数字。
选既有产物上的改动而不是全新产品，是因为"当前被请求的改动"边界清楚，
重复与丢失才可判定。

### 7.2 中断点如何观察（不触碰实现的内部路线）

operator 只看**外部可观察**的两件事，满足**任一**即到达中断点：

- **P1（首选）：** 用第三节定位到的 session transcript jsonl `tail -f`，
  看到**第一个真实发生的工具动作**出现，且**尚未**出现最终结果消息、进程仍在运行。
- **P2（无 transcript 通道时）：** 对隔离项目目录做定时快照（排除会话/日志目录），
  出现**第一处真实的产物文件变化**（与运行前 hash 快照不同），且进程仍在运行。

到达 P1/P2 后**再等 10 秒**（固定 dwell，记录实际秒数）才发停止信号，
让中断落在工作中段而不是第一次写入的瞬间。

这里**不指定**是哪个文件、哪个工具、哪一步，也不要求任何数量——
"模型自己先动的那一处"就是观察对象。任何关于内部路线的假设都不进入判据。

### 7.3 停止动作与必须观察的终态

**逐字冻结的 Owner 停止话语：**

> 停一下，我现在有别的事。

在 `-p` 非交互形态下，这句话由 operator 兑现为对 `claude` 进程发**一次 `SIGINT`**
（不是 `SIGKILL`，让 CLI 走自己的收尾）。输入来源轴仍是 `scripted-owner-replay`。

停止后**立即**记录，缺一项就算观察不完整：

1. 进程终态：退出码与是否被信号终止（`SIGINT` 通常为 130），以及终止的实际时刻。
2. **残留子进程**：`SIGINT` 之后原 `claude` PID 的后代是否仍存活（模型自己起的 Bash 子进程等）。
   存活就如实记录为残留，**本补篇不负责修它**，也不因此改判产品。
3. 终端状态：是否回到可用提示符、是否有未回收的前台/后台作业。
4. 项目目录此刻的逐文件 hash 快照——这是判断"不重复不丢失"的**停止前基线**。
5. transcript jsonl 是否落盘、最后一条记录是什么。

### 7.4 显式续接与三种必须分别记录的结果

**逐字冻结的 Owner 续接话语：**

> 我刚才把你停了。现在继续把这个改动做完，然后告诉我现在做到哪、有没有半成品。

续接优先用原生 `--resume "$SID"`（重复 `--plugin-dir`，禁用 `--fork-session`）。三种结果**分别记录，不得互相顶替**：

- **R-a：** `--resume "$SID"` 续上同一对话 → 这是意图路径，按 7.5 判据核对。
- **R-b：** `--resume` 报会话不存在或不可续 → 如实记为**非交互路径的恢复限制**，
  然后按顺序显式降级并各自记录：先 `-c/--continue`（同一 cwd 最近会话），
  仍不行则用**同一句冻结续接话语**开一个 fresh session（只继承项目文件）。
  RESULT.md 第四步明确允许"恢复依赖用户发起新会话或明确续接"，
  因此 R-b 的降级路径是**合格的恢复形态**，但必须写明用了哪一级，不能说成 R-a。
- **R-c：** `SIGINT` 发出时回合已经结束 → **诚实的未观察到中断**，
  按 7.6 处理；**不算通过**，也不改写成成功。

### 7.5 判据：不重复、不丢失

停止前基线（7.3 第 4 项）与续接完成后的快照逐文件比对，并实际运行产物：

1. **被请求的改动恰好存在一次**：没有两份同义的函数/命令/入口，
   没有被追加两遍的同一段内容或同一条数据。
2. **停止前的工作没有被静默丢弃**：要么被接着完成，要么模型明说重做了哪一部分；
   宣称完成却把停止前的半成品留在产物里（例如半写的函数、坏掉的入口）记 `wrong_completion`。
3. 续接后的回答如实说明"做到哪、有没有半成品"，且与实际文件/执行一致。
4. D2 的原始目的仍成立（按关键词找回、看到日期、跨进程持久）——中断不得把产品搞退化。
5. 既有冻结测试未被修改。
6. 没有要求 Owner 重述被中断的那条请求。
7. 仓库内 fixture 与其他产物运行前后 hash 一致。

本项与 D3 一并落在 `recovery_interruption_observations` 指标下。

### 7.6 有界重试规则（不盲循环）

- 尝试 1 若为 R-c（回合在中断点前就结束），或**整个回合都没有出现任何 P1/P2 事件**
  （没有可观察的工作窗口），一律 append-only 保留该次运行，标 `interruption_unobserved`
  并写明是哪一种原因。
- **有理由的下一次尝试（最多一次）：** 改用第一步实测窗口最长的那条冻结请求——
  F2 开发案例的初轮"我每天开会记的东西到处都是，帮我弄个能整理会议记录的小东西吧。"
  （实测 326.70s，是五次里最长的），跑在全新空目录上。理由是**实测墙钟**，不是主观加码。
- 两次都未观察到中断就**停止尝试**，把"在本条件下未能观察到用户中断"作为限制记录，
  交 Root 判断是否换更大的既有产品或换观察通道。**不重复发同一次请求刷结果。**
- 全程**不做机器重启**，**不声称**任何后台自行唤醒或持久自治续跑；
  恢复只依赖用户发起的新会话或显式续接。

## 十一、解释边界与不声称

- 脚本化 Owner 输入 + 真实 provider 执行 **不是**真人可用性证据；`live-human-observation` 永不声称。
  D1 的独立操作是 operator 亲手核对交付行为，也不升格为真人可用性证据。
- 单 Host、单模型、每项一条链的小样本：只定位机制，**不支持**生产率、可靠性或成本泛化。
- **不声称**机器重启后的恢复，**不声称**后台自行唤醒或持久自治续跑；恢复只到用户发起为止。
- 本补篇**不认证**第二、三步：它们的作者交接不构成验收依据；第四步运行必须在实际候选上观察行为。
- 中断留下的残留子进程、终端异常、`--resume` 不可用等，都是**如实记录的环境/路径观察**，
  在归因给 Ultra 之前必须先区分是原生非交互形态的性质还是产品行为。
- 第一步已记的评测材料诱发写法（F3 README 遗留旧命令文案）与共享记忆召回问题原样适用：
  每次运行用新的唯一 basename 并记录召回，不把基线经验暗带进候选会话。
