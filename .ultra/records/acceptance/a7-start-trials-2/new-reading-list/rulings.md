# Rulings

Decisions made without asking the Owner. The Owner reads this log at milestone gates. The
current design they shaped is in `.ultra/design.md`.

- 2026-11-12 L2 裁决：build on Node.js (v25.7.0, already installed) with the standard library only, no npm dependency and no build step, tested with the built-in `node --test` runner — 因为 the Owner (by proxy) wants it to run with what is already installed and with no third-party packages (interview Q3, Q4), and Node's built-in runner prints a named line per test that a check can match (design.md Facts 1–2) — 如果判断错了，代价是 rewriting a few hundred lines in another language while the data file and the requirements stay as they are
- 2026-11-12 L2 裁决：keep the whole list in one JSON file, `~/.reading-list.json` by default and overridden by the environment variable `READING_LIST_FILE`, and write each change to a temporary file in the same directory that is then renamed over the list — 因为 the Owner (by proxy) wants a plain file they can open and back up that the tool never garbles, even on Ctrl-C (interview Q2), rename(2) always leaves either the old or the new file (design.md Fact 4), and each check needs its own file — 如果判断错了，代价是 a one-time migration of the data file to another format or place
- 2026-11-12 L1 裁决：a link is the normalized `href` that `new URL()` gives for an `http:` or `https:` URL with a host, and two links are the same when those normalized forms are equal (`HTTPS://Example.COM` and `https://example.com/` are one link; `/a` and `/a/` are two) — 因为 `new URL()` alone accepts `javascript:`, `file:` and `mailto:` links (design.md Fact 3), and the Owner (by proxy) wants only web addresses and no duplicate entries (interview Q5) — 如果判断错了，代价是 a link the Owner sees as a duplicate is saved twice, or a non-web link they want is refused; widening the rule later is an L1 add, not a reduction
- 2026-11-12 L1 裁决：each entry gets the next number when it is added; numbers are never reused or renumbered, and re-adding a read link keeps its number and its stored title — 因为 the Owner (by proxy) marks items by the number the list shows (interview Q5), and position numbers would shift after every mark, so a number read from an older listing could mark the wrong item — 如果判断错了，代价是 numbers that keep growing instead of restarting at 1, and a new title given on re-add that is not kept
- 2026-11-12 L1 裁决：a data file that exists but cannot be read as a list is never written; every command stops with a message naming the file and exits non-zero — 因为 the Owner (by proxy) says nothing saved may ever go missing or get garbled (interview Q2), and replacing an unreadable file with an empty list would lose all of it — 如果判断错了，代价是 the Owner has to repair or move the file by hand before the tool works again
- 2026-11-12 L3 裁决：one milestone holds every requirement (add, a known link, list unread, mark read, an unreadable data file, the README), and its journey walks add → list → mark read → list through the real command; the milestone split was not put to the Owner — 因为 three small behaviors that are only useful together make one deliverable, and a split would add a gate without giving the Owner anything usable earlier — 如果判断错了，代价是 the Owner sees nothing until the whole list works, a few nodes later than with a split
