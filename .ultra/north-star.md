# Project North Star

> **Authority**: the accepted steering contract for this repository. Every active
> Change, task, artifact, and verification claim must trace to it.

## Project Direction

Deliver Ultra Builder Pro as a portable, file-first workflow plugin whose complete
primary path remains usable and recoverable across five coding CLI hosts.

## North Star Outcome

- `NS-01` outcome: an owner can carry one real software change from intent through
  research, implementation, verification, cross-host continuation, and delivery using
  repository files plus Git as the recoverable authority.
- Metric or observation contract: all five installed host surfaces expose the same
  fourteen Skills and five Hooks, pass Doctor, and complete the relevant real-path
  acceptance without orphan canonical artifacts.
- Why it represents delivered value: the workflow is useful only when another session
  or supported host can understand, continue, verify, and recover the work.

## Hard Constraints

- `HC-1`: Claude Code, Codex, OpenCode, Kimi Code, and Grok Build receive the same
  fourteen-Skill product through host-native plugin or bundle surfaces.
- `HC-2`: Owner-invoked workflows remain explicit; model-invoked disciplines are
  selected by the model only inside an already authorized task.
- `HC-3`: Project truth remains owner-readable files plus Git. Do not restore an Ultra
  database, MCP kernel, semantic state machine, prompt projection, or daemon.
- `HC-4`: Every canonical artifact has a named writer, consumer, freshness rule, and
  recovery route. Generated observations never become semantic authority.
- `HC-5`: Delegation grants no new authority. Instructions, permissions, worktree
  changes, receipts, timeout, cancellation, and recovery remain inspectable.
- `HC-6`: Commit, push, publication, real HOME installation, and authenticated provider
  calls remain separately authorized external effects.

## Explicit Exclusions

- No Ultra-owned general conversation memory, code graph, deployment provider, or
  framework guidance.
- No custom-agent projection required for semantic portability; focused methods travel
  as Skill references and may use native bounded subagents when a host supports them.
